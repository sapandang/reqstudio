# REQ Studio Architecture

This document describes the overall architecture of the **REQ Studio** VS Code extension so new contributors can understand the codebase and make changes confidently.

---

## 1. Overview

REQ Studio is a VS Code extension that provides a visual HTTP/REST API client for `.req` files. When you open a `.req` file, VS Code launches a **Custom Webview Editor** rendered by a Vue 3 frontend. The extension backend (Node.js/TypeScript) handles:

- Reading/writing `.req` JSON files
- Executing HTTP requests via `node-fetch`
- Environment variable substitution (`{{VAR}}`)
- File uploads (multipart & binary)
- Streaming response handling

## 3. The Two Worlds: Extension Host vs Webview

VS Code extensions run in a **Node.js Extension Host** process. The editor UI runs inside a **Webview**, which is essentially an isolated iframe with limited capabilities. They communicate exclusively via **asynchronous message passing**.

```
+-------------------------------------------------+
| VS Code Window                                  |
|  +-------------------------------------------+  |
|  | Extension Host  (Node.js)                 |  |
|  |  src/extension.ts                         |  |
|  |    - ReqCustomEditorProvider              |  |
|  |    - HTTP request execution               |  |
|  |    - File I/O                             |  |
|  +-------------------------------------------+  |
|              | postMessage / onDidReceiveMessage |
|  +-------------------------------------------+  |
|  | Webview  (Chromium iframe)                |  |
|  |  media/dist/index.html                    |  |
|  |    Vue 3 app -> Requester.vue             |  |
|  +-------------------------------------------+  |
+-------------------------------------------------+
```

### Why this matters
- **You cannot use Node.js APIs inside the Vue component.** No `fs`, no `path`, no `fetch` (use `vscode.postMessage` to ask the extension host instead).
- **You cannot use DOM APIs inside `extension.ts`.** The backend never touches the UI directly.
- Any state that needs to persist must be serialized to the `.req` file by the extension host.

## 4. Data Flow

### 4.1 Opening a `.req` File

1. User clicks a `.req` file in VS Code.
2. VS Code activates the extension (`onCustomEditor:req-studio-ui.reqCustomEditor`).
3. `ReqCustomEditorProvider.openCustomDocument()` reads the file and creates a `ReqDocument` (parses JSON).
4. `resolveCustomEditor()`:
   - Reads `media/dist/index.html`, injects webview URIs for assets.
   - Sends `load-request` message to the webview containing `document.documentData`.
   - Scans the workspace root directory and relative directory for `.reqenv` files and sends `load-environments` (relative `.reqenv` files override root ones of the same name).
5. The Vue app receives `load-request` and calls `setRequestData()` to populate the UI.

### 4.2 Editing a Request

1. User changes any field in the UI (URL, headers, body, etc.).
2. Vue's `watch(requestData, ...)` detects the change.
3. The watch handler posts `document-changed` with the current request JSON.
4. The extension host receives it, calls `document.update(data)`, and fires `onDidChangeCustomDocument`.
5. VS Code marks the document tab as **dirty** (unsaved changes).

### 4.3 Saving a Request

1. User presses `Ctrl+S`.
2. VS Code invokes `saveCustomDocument()`.
3. The extension host serializes `document.documentData` to formatted JSON and writes it to disk.
4. The tab dirty indicator disappears.

> **Note:** There is also an explicit `save-request` message (e.g. from a Save button) which triggers VS Code's save command programmatically.

### 4.4 Sending an HTTP Request

1. User clicks **Send**.
2. Vue posts `send-request` with:
   - `method`, `url`, `params`, `headers`, `body`, `envFile`
3. Extension host:
   - Reads the selected `.reqenv` file.
   - Substitutes `{{VAR}}` placeholders in URL, headers, body, and params.
   - Appends active query params to the URL.
   - Prepares the body:
     - `raw/text/json/xml` → string
     - `application/x-www-form-urlencoded` → `URLSearchParams`
     - `multipart/form-data` → `FormData` (with file buffer rehydration from base64)
     - `application/octet-stream` → `Buffer` from base64
   - Calls `node-fetch` with `AbortController` for cancellation & timeout.
4. During the response:
   - `response-start` → status + headers sent to webview.
   - `response-chunk` → base64 chunks streamed for large responses.
   - `response-end` → final reassembly and display.
5. Display:
   - Chunks are collected into a `Uint8Array`, decoded via `TextDecoder`, and rendered in a read-only textarea.

### 4.5 Cancelling a Request

1. User clicks **Cancel**.
2. Vue posts `cancel-request`.
3. Extension host calls `AbortController.abort()`.
4. `node-fetch` throws `AbortError`; extension distinguishes user cancellation from timeout.

## 5. The `.req` File Format

`.req` files are plain JSON. Here is the full schema:

```json
{
  "description": "Get user profile",
  "method": "GET",
  "url": "http://localhost:3000/api/users/1",
  "params": [
    { "key": "debug", "value": "true", "enabled": true }
  ],
  "headers": [
    { "key": "Authorization", "value": "Bearer {{token}}", "enabled": true }
  ],
  "bodyType": "application/json",
  "bodyText": "{\\"name\\": \"test\\"}",
  "bodyUrlEncoded": [
    { "key": "field", "value": "value", "enabled": true }
  ],
  "bodyMultipart": [
    { "key": "file", "value": null, "type": "file", "enabled": true }
  ]
}
```

| Field | Type | Description |
|-------|------|-------------|
| `description` | `string` | Human-readable label for the request |
| `method` | `string` | HTTP method: `GET`, `POST`, `PUT`, `DELETE`, ... |
| `url` | `string` | Target URL (env vars substituted at send time) |
| `params` | `Array<{key, value, enabled}>` | Query parameters |
| `headers` | `Array<{key, value, enabled}>` | Request headers |
| `bodyType` | `string` | Body mode: `none`, `raw`, `text/plain`, `application/json`, `application/x-www-form-urlencoded`, `multipart/form-data`, `application/xml`, `application/octet-stream` |
| `bodyText` | `string` | Payload for raw/text/json/xml |
| `bodyUrlEncoded` | `Array<{key, value, enabled}>` | Form fields |
| `bodyMultipart` | `Array<{key, value, type, enabled}>` | Multipart parts; `type` = `text` or `file`. Files are **not** saved in the `.req` file (`value` is `null` on disk). |

> **File uploads:** When a user selects a file in the webview, it is read via `FileReader` to base64, sent to the extension host inside the `send-request` message, and converted back to a `Buffer` before `node-fetch`. The base64 content is **not** persisted to the `.req` file.

## 6. Environment Variables (`.reqenv`)

Environment files live next to `.req` files. Two formats are supported:

1. **JSON** — parsed directly.
2. **Dotenv** — `KEY=value` lines, `#` comments ignored.

The extension auto-discovers files ending in `.reqenv` from both the workspace root directory and the same directory as the `.req` file. If an environment file with the same name exists in both directories, the relative file overrides the root-level file. A file named `.reqenv` is treated as the **default** environment.

Example `.reqenv`:
```
baseUrl=http://localhost:3000
apiKey=secret123
```

Usage in a request:
```json
{ "url": "{{baseUrl}}/api/test" }
```

Substitution happens **at send time**, not at save time. This allows the same `.req` file to work across dev/staging/prod by swapping env files.

## 7. Frontend Deep Dive (`media/`)

### 7.1 Tech Stack
- **Vue 3** (Composition API + `<script setup>`)
- **Vite** (build tool)
- **Tailwind CSS v4** — utility-first styling
- **@vscode-elements/elements** — VS Code-native web components (textfield, button, tabs, etc.)

### 7.2 Build
Run inside `media/`:
```bash
cd media
npm install
npm run build   # outputs to media/dist/
```

The extension host **serves the built `dist/` folder**, not the raw Vue source. `vite.config.js` marks `vscode-*` tags as custom elements so Vue does not try to compile them.

### 7.3 UI Component (`Requester.vue`)

This is a single large Vue component that holds all UI state. Key sections:

```
Template
  - Description field
  - Environment selector
  - Method + URL + Send/Cancel + Export
  - Tabs: Parameters | Body | Headers
  - Response pane: Status, Time, Body, Headers
  - Export Code Modal (Language selector: cURL, JS fetch, Axios, Python, Go, Java; preview & copy button)

Helper Modules
  - `codeGen.js` — Code snippet generator converting request data (URL, method, headers, query params, body) into multi-language snippets.

Script
  - Refs for all request fields
  - Computed: requestData (derived from all refs)
  - Watch: requestData -> posts document-changed
  - Watch: selectedEnvFile -> posts env-changed
  - Message listener: handles load-request, response-*, etc.
  - getRequestData() / setRequestData()  <--- serialize/deserialize
```

**If you add a new field to the request UI, you MUST:**
1. Add a `ref('')` or appropriate default.
2. Bind it in the template with `v-model`.
3. Include it in `getRequestData()` so it gets sent to the extension.
4. Restore it in `setRequestData()` so it loads from disk.

## 8. Backend Deep Dive (`src/extension.ts`)

### 8.1 Classes

#### `ReqDocument`
Implements `vscode.CustomDocument`. Wraps the parsed JSON content of a `.req` file.

```ts
class ReqDocument implements vscode.CustomDocument {
  uri: vscode.Uri;
  private _documentData: any;

  constructor(uri, initialContent: Uint8Array)
  get documentData(): any
  update(newData: any): void
}
```

#### `ReqCustomEditorProvider`
Implements `vscode.CustomEditorProvider<ReqDocument>`. This is the heart of the extension.

Key responsibilities:
- `resolveCustomEditor()` — builds the HTML, sets up message handlers.
- `send-request` handler — run the HTTP request lifecycle.
- `document-changed` / `save-request` handlers — sync state to `ReqDocument`.
- `_applyEnvToMessage()` — env var substitution before fetch.
- `prepareBodyAndHeaders()` — convert webview payload to Node.js-compatible fetch args.

### 8.2 Request Lifecycle (Backend)

```
receive send-request
    |
    v
_applyEnvToMessage()   -- substitute {{vars}}
    |
    v
prepareBodyAndHeaders() -- build FormData / Buffer / string body
    |
    v
node-fetch() with AbortController
    |
    v
response-start  ----> webview
response-chunk  ----> webview  (repeated)
response-end    ----> webview
```

**Streaming:** The extension reads `res.body` as an async iterator, base64-encodes each chunk, and sends it individually. The webview reassembles. This avoids loading multi-megabyte responses into the extension host's memory all at once.

**Generation tracking:** Each `send-request` gets a monotonically increasing generation number. If a newer request is started while a previous one is still streaming, stale chunks are discarded (`_isStale()`).

## 9. Development Workflow

### 9.1 Setup

```bash
# 1. Clone & install backend dependencies
git clone <repo>
cd reqstudio
npm install

# 2. Install & build frontend
cd media
npm install
npm run build
cd ..

# 3. Compile extension TypeScript
npm run compile
```

### 9.2 Running in VS Code

Press `F5` (or Run → Start Debugging) to open a new **Extension Development Host** window. In that window:
- Open a folder containing `.req` files.
- Click a `.req` file to open the custom editor.

### 9.3 Testing with TestApp

```bash
cd TestApp
npm install
npm start   # runs on http://localhost:3456
```

Then create a `.req` file pointing to `http://localhost:3456/api/test`.

### 9.4 Making Frontend Changes

If you edit `media/Requester.vue` (or any media file):
```bash
cd media
npm run build
```
Then reload the Extension Development Host (`Ctrl+R` or `Cmd+R` in the webview dev tools).

> You can run `vite` dev server for faster iteration, but the extension **always serves `media/dist/`**. The dev server is only useful for rapid Vue compilation checks; you still need to `npm run build` before the extension sees changes.

### 9.5 Making Backend Changes

Edit `src/extension.ts`, then:
```bash
npm run compile
```
Reload the Extension Development Host.

## 10. Common Tasks for Contributors

### Adding a New Request Body Type
1. **Frontend:** Add an option to the body type `<vscode-single-select>` in `Requester.vue`.
2. **Frontend:** Add the corresponding UI panel (v-if) to collect data.
3. **Frontend:** Update `getRequestData()` and `setRequestData()` to include the new field.
4. **Backend:** In `prepareBodyAndHeaders()` inside `extension.ts`, add a branch to transform the new body type into a fetch-compatible payload.

### Adding a New UI Field
1. Add a `ref()` in `Requester.vue`.
2. Bind it with `v-model` in the template.
3. Add it to `getRequestData()` (serializes to JSON).
4. Add it to `setRequestData()` (restores from JSON).
5. No extension.ts changes needed — the document is saved/loaded generically.

### Adding a New Setting
1. Declare it in the root `package.json` under `contributes.configuration.properties`.
2. Read it in `extension.ts` via `vscode.workspace.getConfiguration('reqstudio').get('key')`.

### Changing Environment Variable Syntax
1. Update the regex in `_substituteEnvVars()` in `extension.ts`.
2. Be careful: this affects **all** fields (URL, headers, body, params).

## 13. Troubleshooting

| Symptom | Likely Cause | Fix |
|---------|-------------|-----|
| Webview is blank | `media/dist/` missing or stale | `cd media && npm run build` |
| Changes to `.req` not saving | `getRequestData()` missing the new field | Add field to both getter and setter in `Requester.vue` |
| Env vars not substituting | `.reqenv` file not in same folder as `.req` | Move env file or check filename |
| File upload fails | Base64 not reconstructed correctly | Check `prepareBodyAndHeaders()` for the body type branch |
| Streaming never ends | `response-end` not sent | Ensure fetch loop completes without early return |
| Extension host crashes | Infinite loop in message handler | Check that `watch` does not trigger a message that triggers the watch again |

## 14. Glossary

| Term | Meaning |
|------|---------|
| `.req` | The JSON file format this extension edits |
| `.reqenv` | Environment variable file (JSON or dotenv format) |
| Custom Editor | VS Code API that replaces the default text editor with a webview |
| Webview | An isolated iframe inside VS Code for custom UI |
| Extension Host | The Node.js process where the extension backend runs |
| `postMessage` | The cross-boundary communication API between webview and extension host |
| Generation ID | A counter used to discard stale HTTP response chunks when a new request is fired |
